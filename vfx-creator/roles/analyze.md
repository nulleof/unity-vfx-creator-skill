# Analyze a reference

Inputs are local reference packages or a Unity project and a disposable reference stand. The analysis role can see pack data and reference frames. Treat the packages as read-only.

Use `Inventory` to map families across packs. Pick representatives that cover distinct silhouettes and temporal behavior. Compare variants for reusable construction and differences that merit another recipe. A `Learn` export is a starting point. Scrub onset, peak, negative space, layer overlap and dissipation. Describe highlights, masks and distortions as reproducible shapes. Inspect VFX Graph contexts, exposed properties and cut timing when the snapshot flags a graph approximation. Record script-driven behavior as motion or event timing. For fast strokes, measure how far and how quickly the emitter moves, including changes in direction.

Read `analysis.json` for available graph events, systems, and effective parameter values. If a graph expects named events, capture the relevant sequence with `-GraphEvents`. Use an inclined camera if the silhouette sits on the ground. Check `visibleFrames` and `clippedFrames` in `capture.json` before comparing. Translate the observed event timing and projected shapes into a source-free brief or recipe.

Check the preview conditions when most of an effect is faint or absent. A scripted motion, a named graph event and a textured scene for distortion each require different evidence. For motion-dependent work, record the preview path and separate emitter displacement from the spread of particles. For effects visible only in a scene, describe the environment and interaction they need alongside the captured evidence.

## Source-free brief

- **Action and anchor.** Describe what happens, where it starts, what triggers each beat, and which parts track a transform or stay in world space.
- **View and scale.** Give the camera pitch, framing, resolution, frame rate, capture duration and any preview travel or arc. Describe the ground plane or facing direction, world footprint or travel where measurable, and projected width and height at meaningful times. A pixel box is usable with its resolution and time. For the square orthographic preview, a box extent in pixels divided by the frame size and multiplied by `Framing` gives its approximate extent in the image plane in world units.
- **Beats.** Give time from start, dominant shape, center relative to the anchor, projected width and height, palette and opacity, and how motion and density change. A compact table with time, silhouette, width × height and motion works well. Sample the first visible frame, the main peak of each beat and the late silhouette. Describe quiet intervals. For a loop, give buildup time and a typical post-buildup size range and visible coverage. Note faint remnants and isolated motes when they extend the bounds beyond the shape that carries the action.
- **Layers.** Describe each major shape by its visual role. Include edge softness, gaps, direction, overlap and color hierarchy where they affect recognition. Mark estimates and distinguish the trigger or flash peak from the widest visible silhouette.

Return the brief, capture settings and local capture path to the coordinator. For learning, also return the editable recipe and any approximations. For blind reconstruction, authoring receives the brief's text and numeric observations through a fresh session with the installed skill and clean project. Keep prefab and package names, source metadata, reference frames and target-specific recipes with analysis and review until the candidate is frozen.
